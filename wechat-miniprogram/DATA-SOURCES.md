# 🧭 数据源接入指南（重要）

本指南说明自动获取抢票信息的真实情况、如何调参，以及系统如何保证在抓取失败时依然可用。

## 一、当前实测结果（2025-06 真实网络探测）

| 平台 | 实测结果 | 说明 |
|---|---|---|
| 大麦 `search.damai.cn/searchajax.html` | ⛔ 被阿里 **x5sec** 反爬拦截 | 返回 JS 挑战页（`_____tmd_____/punish?x5secdata=...`），纯 HTTP 无法绕过 |
| 猫眼 `m.maoyan.com/ajax/search` | ⛔ WAF 返回 **400** | 需要有效会话（Cookie），数据中心/服务器 IP 更易触发 |
| 保利票务 | ⛔ 候选接口 DNS 失效 / 证书过期 | 官网接口不稳定，需实测 |
| 摩天轮 / 票牛 | ⛔ 404 / 302 | 接口路径需实测，或需登录态 |
| 大麦详情页 | ✅ 部分可访问 | 但需要剧目 ID（搜索被挡后无法自动发现新剧目） |

**结论**：国内票务平台反爬强度高且持续变化，**纯服务器直抓无法保证长期可用**。
本项目为此做了三层设计，保证工具"没有自动数据也能好用"：

1. **社区补录兜底（可靠主路径）**：任何用户手动补录开票时间/链接/场次 → 进共享库 → 所有用户可搜到。
2. **官方渠道链接（无需抓取）**：`theater.enrich` 按「场馆 → 官方票务」映射自动附带官方购票渠道（稳定可用）。
3. **可配置抓取（尽力而为）**：五个数据源全部实现，接口集中配置，可随时更新/开关。

## 二、让自动抓取真正跑起来（按需选择）

### 方式 A：配置有效 Cookie（推荐先试）
1. 用 Chrome 打开大麦/猫眼，正常搜索一次并**通过验证**（能正常看到结果）。
2. F12 → Network → 复制请求头里的 `Cookie`。
3. 粘贴到 `cloudfunctions/fetchShowInfo/sources/config.js` 的 `COOKIE` 字段，重新上传云函数。
4. 说明：Cookie 会过期（数小时~数天），只适合低频个人使用；失效后清空即可。

### 方式 B：验证并更新候选接口
- 保利/摩天轮/票牛的候选接口在 `config.js` 的 `POLLY_ENDPOINTS` / `RESALE_ENDPOINTS`。
- 本地验证方法（项目根目录执行，把 URL 换成实际待测接口）：
  ```bash
  node -e "require('./wechat-miniprogram/cloudfunctions/fetchShowInfo/sources/http.js').getJSON('https://目标接口?keyword='+encodeURIComponent('剧院魅影'),{timeoutMs:8000}).then(d=>console.log(JSON.stringify(d).slice(0,500))).catch(e=>console.error('失败:',e.message))"
  ```
- 把能返回数据的接口写进 `config.js`（支持 `{kw}` 占位符），并让解析结构对齐 `polly.js`/`resale.js` 的 `normalize()`（字段名兼容多种常见命名）。

### 方式 C：接自己的抓取服务（进阶）
- 如果你有可用的抓取服务/代理（如已通过验证的爬虫、第三方数据 API），
  在 `fetchShowInfo/index.js` 的 `search()` 里加一个数据源即可（参考 `sources/` 里任一适配器的结构）。

## 三、架构上的保证

- **缓存**：搜索结果入云数据库，6 小时内不重复抓取；抓不到时旧数据不丢。
- **降级**：任一数据源失败仅影响自身，`Promise.all` 并发 + 6s 超时兜底。
- **合并**：多源按「剧名+城市+年份」归一，主渠道取分最高（有开票时间优先；二手平台降权并标注）。
- **提醒链路与抓取解耦**：开票/开演提醒由用户补录或已入库数据驱动，不依赖实时抓取。

## 四、合规与频率提醒

- 请勿高频抓取：本应用已限流（缓存 6h、每次搜索最多 3 条详情页、单接口 6s 超时）。
- 抓取数据仅用于个人看剧规划，请遵守各平台服务条款，以官方渠道为准。
- 配置 Cookie 属于你本人账号的会话信息，注意保密、勿公开分享。
