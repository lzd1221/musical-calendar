# 🎭 音乐剧助手（微信小程序）— 排期 + 抢票提醒

输入「**剧名 + 年份 + 城市**」→ 自动获取该剧的**抢票平台/链接、开票时间、场次排期** →
关注后自动排日历、检测撞期/上班冲突，并通过**微信订阅消息**在开票前、开演前主动推送提醒。
微信小程序形态，iOS / Android 均支持（当前版本已按 iOS 环境验证兼容，无 iOS 专属限制）。

> 技术栈：原生微信小程序 + 微信云开发（云函数 / 云数据库 / 定时触发器 / 订阅消息）。

## 一、项目结构

```
wechat-miniprogram/
├── project.config.json            # 开发者工具项目配置（填入你的 AppID）
├── miniprogram/                   # 小程序前端
│   ├── app.js                     # 云开发初始化（填环境 ID）
│   ├── app.json / app.wxss / sitemap.json
│   ├── pages/
│   │   ├── index/                 # 首页：剧名-年份-城市搜索 + 热门/历史
│   │   ├── show/                  # 详情：抢票平台/链接、开票倒计时、场次、订阅、补录
│   │   ├── calendar/              # 日历：已关注剧目月历 + 撞期/上班冲突提示
│   │   ├── notify/                # 提醒中心：即将开票/开演清单 + 一键订阅
│   │   └── profile/               # 我的：关注管理、默认城市、关于
│   ├── components/show-card/      # 搜索结果卡片
│   └── utils/                     # date / store / api / notify（订阅消息封装）
└── cloudfunctions/                # 云函数（各自独立部署）
    ├── fetchShowInfo/             # 多平台抓取 + 合并入库（sources/ 为大麦/猫眼/保利适配器）
    ├── watchList/                 # 关注/订阅额度/详情/手动补录
    ├── sendNotify/                # 发送订阅消息（开票/开演提醒）
    └── refreshShowData/           # 定时任务：刷新数据 + 触发提醒（每 5 分钟）
```

## 二、部署步骤（约 30 分钟）

### 1. 前置条件
- 一个已注册的**微信小程序 AppID**（个人主体即可，注册地址 mp.weixin.qq.com）。
- 微信开发者工具（稳定版即可）。
- 小程序类目建议选择「**娱乐 > 演出**」或「**生活服务 > 票务**」，以便申请订阅消息模板。

### 2. 导入项目
1. 打开微信开发者工具 → 「导入项目」→ 选择本目录（`wechat-miniprogram`）。
2. 填入你的 **AppID**（`project.config.json` 里是占位符）。
3. 首次打开会提示云开发未初始化，按提示开通 **云开发**（免费额度足够个人使用）。

### 3. 创建云环境并初始化
1. 云开发控制台 → 创建环境（如 `musical-xxx`），记下**环境 ID**。
2. 修改 `miniprogram/app.js`：`globalData.env = '你的环境ID'`。
3. 云开发控制台 → 数据库 → 创建 4 个集合：
   | 集合 | 说明 |
   |---|---|
   | `shows` | 剧目聚合数据（自动抓取 + 社区补录） |
   | `user_watch` | 用户关注关系 |
   | `user_sub` | 用户订阅提醒额度 |
   | `corrections` | 用户补录/纠错日志 |
4. 集合权限统一设为「**仅创建者可读写**」即可——所有读写都走云函数（云函数不受该权限限制）。

### 4. 申请订阅消息模板
1. mp.weixin.qq.com → 功能 → 订阅消息 → 从公共模板库选用两个模板：
   - **「开票提醒」**：字段建议 `演出名称(thing)` / `开票时间(time)` / `温馨提示(thing)`
   - **「开演提醒」**：字段建议 `演出名称(thing)` / `演出时间(time)` / `场馆(thing)`
2. 把两个**模板 ID** 填入：
   - 前端：`miniprogram/utils/notify.js` 的 `TEMPLATES`
   - 后端：`cloudfunctions/sendNotify/index.js` 的 `TEMPLATES`
3. 若你申请的模板字段顺序不同，同步调整 `sendNotify/index.js` 里的 `ticketData()/showData()` 字段 key（`thing1/time2/thing3`）。微信限制：`thing` 类字段 ≤ 20 字。

> ⚠️ 娱乐类小程序只有**一次性订阅消息**：用户每点一次「允许」= 获得 1 次发送额度。
> 这是微信平台规则，无法绕过；本应用已按此规则做好交互（每场提醒消耗 1 次额度）。

### 5. 部署云函数
在微信开发者工具中，对 `cloudfunctions/` 下每个目录**右键 → 上传并部署（云端安装依赖）**：
- `fetchShowInfo`（数据抓取，需要外网访问权限，控制台确认已开启）
- `watchList`
- `sendNotify`（已在 `config.json` 声明 `subscribeMessage.send` 权限）
- `refreshShowData`（`config.json` 内置每 5 分钟定时触发器；部署后可在控制台确认触发器已生效）

### 6. 验证
1. 编译运行小程序 → 首页搜「剧院魅影」→ 若返回结果即自动抓取生效；
   **若为空，属正常现象**（平台反爬，详见 `DATA-SOURCES.md`），可手动录入体验完整流程。
2. 点进详情 → 复制购票链接、看到开票倒计时（若有）。
3. 点「⭐ 关注」→ 「订阅提醒」→ 授权 → 提醒中心出现该剧。
4. 用「真机预览」扫码在 iOS 微信里测试完整流程。

> 数据抓取的调参指南见同目录 **`DATA-SOURCES.md`**（含各平台实测结果、Cookie 配置、接口验证方法）。

### 7. 部署自检清单（"一直失败"先查这里，按顺序）

| # | 检查项 | 位置 | 不做的后果 |
|---|---|---|---|
| 1 | AppID 已替换 | `project.config.json` 的 `appid` | 无法编译/真机预览 |
| 2 | 云开发环境 ID 已替换 | `miniprogram/app.js` 的 `globalData.env` | 所有云函数调用失败 → 搜索/关注/订阅全部报错 |
| 3 | 4 个云函数都已**上传并部署** | 开发者工具对 `cloudfunctions/` 每个目录右键上传 | 调用报「云函数不存在」 |
| 4 | 4 个数据库集合已创建 | 云开发控制台 | 云函数读写报错 |
| 5 | 订阅消息模板 ID 已填入 | `utils/notify.js` + `cloudfunctions/sendNotify/index.js` | 订阅按钮提示未配置（不影响搜索） |
| 6 | fetchShowInfo 开启**外网访问** | 云开发控制台 → 云函数 → 配置 | 抓取接口全部超时（社区补录不受影响） |

> 排查顺序建议：先在开发者工具 Console 看具体报错信息（如 `env not exists` / `cloud function not found` / `collection not exists`），对应上表处理。

## 三、数据获取说明（重要，请阅读）

自动获取依赖第三方票务平台的公开接口，**存在反爬与改版风险**，本项目做了多层兜底：

| 数据源 | 状态 | 说明 |
|---|---|---|
| 大麦 Damai | ✅ 已启用 | 一手主流票务（含巡演排期）；搜索接口 + 详情页抓取开售时间（限流：每次最多 3 条详情） |
| 猫眼 Maoyan | ✅ 已启用 | 一手主流票务；开票时间在 SPA 内，暂不抓取（可后续扩展） |
| 保利票务 Polly | ✅ 已启用 | 剧院院线官方票务；内置多条候选接口并行尝试，失效自动跳过（`sources/polly.js` 可调整） |
| 剧院官网 Theater | ✅ 已启用 | 按「场馆 → 官方票务」映射自动追加官方购票渠道（官方渠道最权威）；官方公众号无公开接口，靠补录 |
| 摩天轮/票牛 Resale | ✅ 已启用 | 二手/比价平台，**自动降权 + UI 标注「二手/比价」**，仅作补充渠道；信息可能滞后 |
| 社区补录 | ✅ 内置 | 任何用户可手动补录开票时间/链接/场次，入库后所有用户共享（`corrections` → `shows`） |

**兜底策略**：抓取失败或接口变更 → 搜索页提示手动录入 → 数据进入共享库 → 后续搜索命中共享数据。
**请勿高频抓取**（本应用已限流：缓存 6 小时、每次搜索最多 3 条详情页、候选接口 6 秒超时），超出即可能被平台风控。
**多源合并规则**：同一剧目按「剧名+城市+年份」归一合并；主渠道取分最高者（有开票时间优先，大麦/猫眼/保利/剧院官网权重高于二手平台）；其他来源进入「其他购票渠道」列表。

## 四、iOS 说明

- 小程序天然双端兼容；本项目未使用任何 Android 专属 API，iOS 微信内运行无特殊配置。
- 购票链接：微信小程序内**无法用 web-view 打开外部购票页**（业务域名限制，iOS/Android 一致），
  应用采用「复制链接 → 在微信聊天/系统浏览器打开」的方式，iOS 上复制到 Safari 即可。
- 订阅消息推送与操作系统无关，走微信通道；iOS 用户需允许微信通知。
- 若后续要「仅 iOS 可用」，可在云函数按 `wx.getDeviceInfo()` 的设备型号做灰度，但一般无此必要。

## 五、常见问题（FAQ）

**Q：搜索没有结果？**
A：可能原因：剧名未收录 / 尚未开票 / **平台反爬拦截（当前普遍现象）**。建议：
先不带年份、只搜剧名；仍无结果则点「手动录入」，填写开票时间后即可获得提醒；
想启用自动抓取，按 `DATA-SOURCES.md` 配置 Cookie 或验证接口。

**Q：订阅了但收不到消息？**
A：① 检查模板 ID 是否已配置且与字段匹配；② 用户授权时若点了「总是保持以上选择/拒绝」会收不到；
③ 一次性订阅额度用完（每授权 1 次 = 1 次提醒）；④ 定时触发器是否部署成功。

**Q：开票时间不准？**
A：自动抓取的开票时间以详情页为准，可能有偏差；发现错误可在详情页手动补录纠错，会立即生效并共享。

**Q：云函数报 403 / 网络错误？**
A：`fetchShowInfo` 需要外网访问，云开发控制台确认该函数已开启外网访问；部分平台会封数据中心 IP，属正常现象，靠兜底策略工作。

**Q：数据库集合权限？**
A：云函数用管理员权限读写，集合权限设「仅创建者可读写」即可，无需开放客户端直读。

## 六、与本地 HTML 工具的关系

仓库根目录的 `musical-calendar.html` 是**离线单文件版**（手动录入、本地存储、智能排期算法）；
本小程序是**联网增强版**（自动抓取、订阅推送、多端同步、社区数据）。两者数据模型兼容，可配合使用：
HTML 版适合快速规划，小程序版适合日常跟进抢票。
